## 如果你也经历过这些时刻

你并不是没有想法。恰恰相反，问题常常是想法来得太快、太完整。

一个项目刚冒出来时，你很快就能看见它的全貌：怎么做、哪里会出问题，甚至做成以后会是什么样。可等到真正动手，剩下的却是漫长、具体又不完美的执行。刚才还很兴奋，转眼就像被拔掉了电源。

更麻烦的是，执行的时候还会不断出现新点子。它们比手上的工作新鲜，也更让人想追下去。你不想丢掉它们，于是先查一点、再展开一点，回过神时，原来的事情已经被放在一边。

这很容易让人怀疑自己：为什么明明什么都想到了，却总是做不完？为什么已经换过那么多清单和方法，最后留下的还是一堆没完成的项目？

不是每个 ENTP 都有相同的经历。如果上面这些恰好像你，这个工具才可能对你有用。

## 我是怎么解决的

- **可以有很多主线，但执行时只出现一条。** 其他想做的事没有被删除，只是暂时放进保管箱，不在工作时争夺注意力。
- **新灵感先记一句话，不急着证明它有没有用。** 它进入候审区，不会马上变成任务，也不要求立刻分类整理。
- **没动力时，先去审视以前留下的兴趣。** 有些灵感和主线有关，有些完全无关。整理它们不是为了硬找答案，而是重新找回一点兴趣；想继续原任务、试一个新想法，或者什么都不选，都可以。
- **想明白不算完成，做过的事情才留下记录。** 可以选择能实际运行和验证的工作，记录行动和结果；完成后，它会出现在当天的清单和日历里。不要求每次只做微小步骤。

## 功能怎么用

### 1. 当前主线：别的可能还在，但现在只做这一件

![当前主线页面](designs/readme/01-current-mainline.png)

你可以保存多条主线，每条主线下也可以有多个任务。不过，真正开始做事时，页面只展示当前选择的主线，并突出一个“当前推进”任务。

- 顶部输入框直接创建任务，按回车保存。
- 任务详情可以修改标题并写自由正文，内容会自动保存。
- “暂存新灵感”只记录一句话，不中断当前工作。
- “没动力了”不是在宣布这件事做不下去。它只是打开候审区，让你暂时看看以前感兴趣的东西，再决定要不要回来继续。

其他主线不会和当前主线并排出现。它们统一放在“我的主线任务保管箱”中，可以切换、归档和恢复。归档更像收进储藏室，不会删除任务或 Markdown。

### 2. 候审区：先把灵感留下，不必马上负责

![候审区](designs/readme/02-ideas.png)

候审区不是第二份待办清单。一个想法刚出现时，只写下你不想忘记的那句话就够了。它不必有用，不必和当前主线有关，也不必马上变成一个新项目。

- **未审视**：刚记录，还没有处理。
- **待孵化**：仍然感兴趣，但现在不开始。
- **正在尝试**：愿意为它做一次小实验。
- **已归档**：暂时不看；内容仍然保留，可以恢复。

卡片底部的小图标可以直接完成孵化、尝试或归档。展开卡片后，只有标题、标签和一张空白 Markdown 记录页，没有预设问题和固定分类。

候审区不用每天清空。只有当你想看看自己最近在意什么，或者手上的事情失去吸引力时，再来审视这些想法。

### 3. 今日清单：今天做了什么，今天就记在这里

![今日清单](designs/readme/03-today.png)

今日清单汇总所有主线和收集箱中的当日任务。它是一份按日期保存的账本，不是一张每天凌晨自动重置的临时页面。

- 输入一句话并按回车，可以把任务加入今天的收集箱。
- 支持完成、恢复、分组折叠和优先级排序。
- 支持查看前一天、后一天或从月历选择日期。
- 过期任务由用户决定是否顺延，不会在第二天自动改成“今天”。

任务后来改名，过去的每日账本仍保留当时的标题和所属主线。

### 4. 完成日历：过一段时间，还能看见自己做过什么

![完成日历](designs/readme/04-calendar.png)

任务勾选完成后，会在当天留下完成时间。点击日历中的日期，可以查看那天完成了哪些任务，而不是只看一个没有来历的数字。

如果以后重新打开这个任务，过去的完成记录仍然存在。日历记录的是历史事实，不是任务此刻的状态。

### 5. 生活结构、实验、等待与恢复

以下能力已整合到当前 fork 的源码版；上方已发布的 2.1.9 安装包不包含本次扩展。本次没有生成新的安装包。

| 在哪里 | 如何使用 |
| --- | --- |
| 当前主线 | 点击「添加外部锚点」可直接记录真实外部安排，默认关联焦点任务，可改选或取消关联；如果还没有合适的任务，在「更多信息」里点击「创建新任务」，填写标题并选择主线后会自动关联并回到外部锚点页面，已填写内容保留；保存后回到当前主线，并显示在对应日期的今日结构中。焦点任务点击「进入实验模式」，填写技术问题、实际方法和观察；保存后可继续下一轮、追加证据、暂停或结束总结。「实验历史」可重看已结束实验。草稿和每轮观察在重启后仍保留。 |
| 今日清单 | 输入框下方的「今日结构」默认收起为一行摘要（最近的外部锚点、自主活动和恢复数量），点击展开后可添加和查看记录。它记录真实外部锚点、自主活动和恢复记录。外部来源必填，事件与真实截止分别标明；自主安排不归入外部锚点。点击记录可编辑或结束、取消事件。 |
| 等待事项 | 写明已确认事实、正在等待谁和合理检查日期；应用打开或切页时将到期事项标为「需要检查」。收到信息后手动转为可行动、继续等待或已解决，可归档恢复。 |
| 侧边栏「当前节奏」 | 左下角的节奏菜单在任何页面都可打开：切换推进 / 等待、进入恢复状态、担忧收纳、安静一下。点击「进入恢复状态」隐藏任务、数量和提醒，选择活动或跳过记录；主动退出后回到原页面和输入。恢复会话跨重启保持开启，没有倒计时。 |
| 节奏菜单 | 「担忧收纳」保留现实问题，只需判断有无行动；可关联任务或等待事项。「安静一下」打开不显示生产力信息的记录界面。担忧不自动变成灵感。 |
| 完成日历 | 下方查看最近 14 天结构分布，点击日期查看任务、实验、等待变化和恢复记录；自愿状态记录可只填一项。没有填写的日期保持空白。 |

活动方式「推进 / 等待 / 恢复」由用户控制，与任务完成状态独立。「没动力了」仍然通往候审区。等待且无有效行动的焦点任务收起执行提示，今日任务显示在「依赖外部输入」中；用户仍可主动展开或换一个焦点。

「切换为等待」目前只保存活动方式标记并更新节奏菜单的显示；执行提示的收起由关联等待事项的状态与有效行动决定。

实验在自己的科研、编程环境中运行，软件保存反馈，不执行命令。每轮观察保留完整历史，并关联一条原有任务执行日志；保存实验或结束实验都不完成任务。文件路径只保存引用；「导入文件到备份」会复制用户选择的文件到工作区附件目录，随完整备份恢复。

删除任务仍会先创建完整备份，但现在保留过去的账本、完成事实、执行日志、实验、笔记和图片，解除任务引用。历史页不会因为任务删除或改名而消失。

### 6. Markdown、备份和本地数据

数据保存在本机 SQLite。每条主线、任务、灵感和每日账本还会生成独立 Markdown 文件：

```text
markdown/
├─ 主线/
├─ 任务/
├─ 思路/
├─ 每日/
├─ 实验/
├─ 外部锚点/
├─ 等待事项/
├─ 自主活动/
├─ 恢复/
└─ 担忧/
```

程序只更新文档中的系统区，系统区以外的正文不会被覆盖。文件可以交给 MarkText 或系统默认的 Markdown 软件编辑。

“导出全部”会生成 `.entp.zip`，其中包含数据库、Markdown 和校验清单。导入前，程序会先备份当前工作区。

扩展版使用备份格式 2，同时接受旧格式 1 并升级数据库。旧应用不能导入新格式备份，恢复新数据请使用本 fork 的扩展源码。受管理实验附件会随包保存，外部文件路径对应的文件不会自动打包。

### 7. 直接从 GitHub 更新

左下角可以手动检查 GitHub Releases。程序每天最多自动检查一次；发现新版本后，可以直接下载并覆盖升级，不需要先卸载，也不会打开完整安装向导。安装包通过 SHA-256 校验后才会启动，数据库和 Markdown 不参与覆盖。

## 第一次打开怎么用

初始化版内置了一组介绍数据。它们不是截图或弹窗，而是真正的主线、任务、灵感和完成记录，可以直接操作。

建议先做四步：

1. 在“当前主线”顶部添加一个自己的任务。
2. 把一项任务设为当前任务，只突出眼前要推进的这一件事。
3. 真正做完以后点击“完成当前任务”，完成事实会进入完成日历。
4. 中途想到别的事情时，用“暂存新灵感”记一句话，然后继续当前任务。

示例内容可以修改、完成或归档。产品导览和内部演示只在全新演示工作区中生成，不会覆盖已有数据。本地 D 盘正式部署保持空白初始化，不注入演示内容。

## 为什么要这样设计

这些设计并不是在给 ENTP 下诊断。我只是借助下面几项心理学研究，判断哪些交互可能减少干扰、降低开始行动的难度。它们不能证明软件对每个人都有效，MBTI 也不是临床诊断。

### 目标竞争：为什么执行页只显示一条主线

目标屏蔽（goal shielding）研究讨论了一个正在追求的目标如何抑制其他目标的干扰。当前主线和主线保管箱采用了相同的思路：允许其他目标存在，但不让它们一直出现在执行页面。

参考：Shah、Friedman 与 Kruglanski，[Forgetting All Else: On the Antecedents and Consequences of Goal Shielding](https://doi.org/10.1037/0022-3514.83.6.1261)，2002。

### 注意残留：为什么不鼓励在任务之间来回切换

从未完成的任务切换到另一个任务后，一部分注意仍可能停留在前一个任务上，影响后续表现。软件因此把其他主线移到保管箱，并让新灵感先快速记录，而不是马上展开。

参考：Sophie Leroy，[Why Is It So Hard to Do My Work? The Challenge of Attention Residue When Switching Between Work Tasks](https://doi.org/10.1016/j.obhdp.2009.04.002)，2009。

### 认知卸载：为什么新想法可以先写下来

认知卸载（cognitive offloading）指的是借助纸张、设备或动作，把一部分记忆和信息处理要求转移到外部环境。把灵感写下来，可以减少“必须一直记着它”的负担。这里的目的只是保存，不是立即判断和整理。

参考：Risko 与 Gilbert，[Cognitive Offloading](https://doi.org/10.1016/j.tics.2016.07.002)，2016。

### 实施意图：为什么任务需要具体的下一步

实施意图研究关注“在什么情况下，采取什么行动”这种具体计划。相比只写一个抽象目标，明确行动条件和动作更容易启动行为。当前版本用短任务和子任务承载可立即开始的行动，但还没有单独的“下一步最小行动”字段。

参考：Gollwitzer 与 Sheeran，[Implementation Intentions and Goal Achievement: A Meta-analysis of Effects and Processes](https://doi.org/10.1016/S0065-2601(06)38002-1)，2006。

### 新奇刺激：为什么新灵感很容易抢走注意

有关新奇刺激的研究发现，人脑的 SN/VTA 等区域会对新刺激作出反应，新奇性也与学习和探索有关。这能解释为什么新想法可能比已经熟悉的任务更有吸引力。候审区没有消灭这种兴趣，只是把“记录新想法”和“马上换任务”分开。

这项研究针对一般的新奇加工，不能用来证明某种人格类型具有特定脑机制。

参考：Bunzeck 与 Düzel，[Absolute Coding of Stimulus Novelty in the Human Substantia Nigra/VTA](https://doi.org/10.1016/j.neuron.2006.06.021)，2006。

## 项目的范围

最初的产品研究还讨论过情绪表达、沟通方式、7/14/30 天承诺周期和周期复选。这些内容没有完整进入 2.0：

- 情绪翻译器和对话模式识别尚未开发。
- 承诺期限与复盘日期没有作为 2.0 功能开放。
- 灵感关联、灵感验证记录和转任务已有部分数据能力，当前 Flet 页面尚未全部开放；新增任务实验闭环独立于灵感验证。

当前源码扩展在原有好奇心回流流程上增加生活结构、技术实验、外部等待和自主恢复，不增加效率排名、连续打卡或心理诊断。

## 下载和安装

[直接下载 Windows 安装版](https://github.com/TANGuoGUO/entp-manual/releases/latest/download/ENTP-Manual-2.1.9-Setup.exe)

安装时可以选择安装目录、桌面快捷方式，以及是否在登录 Windows 后于后台启动。程序支持系统托盘隐藏和标准 Windows 卸载。

安装版的用户数据保存在：

```text
%LOCALAPPDATA%\ENTP自强手册
```

卸载默认保留数据库和 Markdown，避免误删个人记录。详细说明见 [WINDOWS_INSTALLER.md](WINDOWS_INSTALLER.md)。

## 从源码运行

环境：Windows、Python 3.12。

```bat
cd /d D:\Code
git clone https://github.com/huang46u/entp-manual.git
cd entp-manual
call workspace-env.cmd
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-flet.txt
.\.venv\Scripts\python.exe flet_app.py
```

本地 Windows 部署请使用 `start-local.cmd`。准备依赖时，在 cmd 中先 `call workspace-env.cmd` 再执行 Python 命令，使临时文件、依赖缓存和运行数据留在工作区。

新增功能的针对性测试（cmd）：

```bat
call workspace-env.cmd
.venv\Scripts\python.exe -m unittest tests.test_life_structure tests.test_structure_ui tests.test_task_deletion tests.test_backup_restore
```

构建安装包需要 Inno Setup 6，具体命令见 [WINDOWS_INSTALLER.md](WINDOWS_INSTALLER.md)。测试设计和报告见 [TEST_PLAN.md](TEST_PLAN.md) 与 [TEST_REPORT.md](TEST_REPORT.md)。第三方组件及许可证说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
